# Vault price row freshness

Status: **implemented**. Written and implemented 2026-09-28.

## Problem and current behaviour

The historical EVM reader suppresses a sampled row when its values remain within the change threshold. Ordinary ERC-4626 readers compare share price, total assets and supply; share-price-equivalent readers compare only share price. The comparison cache starts empty on each scan, so the first successful read in a new scan normally writes a row. That incidental behaviour is not a durable two-week contract: a vault may not be polled in a short scan, contextual readers have a separate filter, and native feeds have separate writers. `write_all_samples=True` already preserves every observation for a dedicated issuer-NAV feed, but the all-chain EVM scanner does not use it.

The raw row's `timestamp` is the source observation time; `written_at` is the Parquet publication time. A recent `written_at` on an old observation must never count as fresh data. Existing price history and reader state are critical production state, particularly on Monad.

## Freshness policy

- Define a single named **meaningful TVL** entry limit of **USD 1,500**, matching `VaultReaderState.min_tvl_threshold`, and a maximum **14-day age of the latest actual source observation** at each successful live scan publication. A previously qualified vault remains in the certified set until its observed USD TVL falls below the existing $1,000 tiny-vault boundary; this hysteresis avoids flapping near $1,500. Document that $10,000 is the separate hourly polling boundary. The existing deposit-activity rule may still limit historical backfills, but must not exclude a discovered vault whose live TVL meets the meaningful limit from freshness observations.
- Assess TVL from the current successful observation in denomination-token units using the existing `VaultReaderState.exchange_rate` path and its protocol overrides; do not compare raw ETH/BTC token amounts with a USD limit. Reuse the converted `last_tvl` calculation, or extract the conversion into one helper shared by reader state and freshness decisions. Detect `UNKNOWN_EXCHANGE_RATE` using the named constant *before* multiplying. Do not introduce a second currency-rate table or treat the `0.99` sentinel as a verified USD quote. Retain genuine periodic observations for unknown-conversion vaults, but exclude them from USD certification and report them under a distinct reason.
- Retain an unchanged **genuine** EVM observation once the previous retained row is seven days old. Ordinary EVM readers also keep their first successful sample in every scan. Contextual readers can only retain observations present in their source history, and native feed writers already keep their own real source rows. Never manufacture timestamps or prices. Keep `write_all_samples=True` behaviour for dedicated issuer feeds.
- Apply the retention rule only to routine live scans. Historical backfills keep their existing sparse sampling. At each successful publication, audit the newest real source timestamp against the 14-day limit and report any eligible vault that is overdue. A source outage or missing contextual event cannot be repaired by the retention rule; it remains an explicit diagnostic.

## Implementation steps

1. **Map and centralise observation eligibility.** Identify all active routes into `vault-prices-1h.parquet`: `scan_historical_prices_to_parquet()`, contextual readers (Rysk and Flying Tulip), dedicated tokenised-fund scans, and native merge paths in `eth_defi/vault/post_processing.py`. Record which feeds already emit current observations and which only emit change events. Add a bounded current-state TVL probe for discovered vaults rejected by `passes_price_scan_activity_filter()` so meaningful low-activity vaults still enter the live freshness scan; do not use this probe to trigger a genesis-to-head backfill, especially on Monad. Log genuinely unreadable or uninstantiable vaults as unverified. Put the TVL threshold and maximum age in one shared policy module or constants used by the scanner and documentation. Preserve protocol-specific exchange-rate overrides.
2. **Track the previous retained source timestamp without changing sparse-value semantics.** Before the EVM writer replaces its scan range, derive each selected vault's last retained observation before `start_block` from the already loaded raw Parquet table. Use the stored peak TVL for the $1,500/$1,000 hysteresis instead of persisting a second qualification flag. Leave the ordinary reader's empty per-scan value cache and first-row behaviour intact. Advance the timestamp only when a row is retained. Preserve older Monad rows and the atomic replacement path.
3. **Apply the seven-day retention interval to live EVM observations.** Add the time condition alongside the existing change condition for static and contextual EVM readers without suppressing the first row of an ordinary EVM scan. Unknown-conversion vaults can retain real samples but cannot be certified against a USD limit. Native feeds retain the source rows supplied by their own writers. Where the source has no fresh observation, emit an overdue diagnostic rather than a false heartbeat.
4. **Keep source and publication time distinct.** The raw price writer retains genuine observations and audits their source timestamps. The cleaning pipeline can remove rows for metadata, denomination, activity or quality reasons; its output has no independent 14-day guarantee. Preserve `written_at` semantics and the existing Parquet schema. Keep the EVM writer's atomic replacement path, abort on migration errors, and preserve pre-boundary Monad history.
5. **Make the result observable.** Report eligible vault count, freshness rows written, and overdue/unknown-conversion vaults per chain/feed. Check the newest source `timestamp`, never `written_at`, against the successful scan's source horizon; distinguish scan gaps, RPC/API errors, and unavailable currency conversion. Report low-activity vaults that qualify through the current-state probe and those whose TVL cannot be verified; activity alone must not remove a known meaningful vault from overdue reporting. An operator should be able to tell when the two-week condition was not met.

## Implementation record

The live EVM scanner now probes low-activity vaults using the existing reader-state USD conversion, retains real unchanged observations after seven days, and reports qualified vaults whose latest source row exceeds 14 days. Native feed merges audit their real source timestamps. Eligibility is derived from already persisted latest and peak TVL; a stateful continuation starts after its last processed block so a quiet scan preserves the previous row. The row TypedDicts, reader docstrings and scanner narratives now state the limits and source-time semantics.

Focused offline verification on 2026-09-28 passed: 14 tests covering converted TVL, qualification hysteresis, static and contextual retention, overlapping file-backed Parquet scans, a quiet and overdue scan, native source-time auditing, and historical formatting. Scheduled scans and healthy providers remain necessary for a calendar-time guarantee; source gaps are surfaced as overdue diagnostics instead of fabricated rows.

A high-effort Kimi K3 code review on 2026-09-28 identified missing-reader reporting and inconsistent contextual exchange-rate lookup; both were fixed and the focused tests passed. Its final follow-up found no unresolved high-confidence bug in the reviewed excerpts. The review was limited to the supplied freshness and audit code, so the full scanner remains subject to normal PR review.
